# 在美华人第三国签证申请助手：初步产品文档

> 文档状态：初稿  
> 当前阶段：产品定义  
> 更新日期：2026-06-23

## 1. 项目概述

本项目面向持中国护照、目前在美国居住或停留的用户，为其申请加拿大、日本、韩国等第三国签证提供分步骤操作指导。首要服务对象是持 F、H、J、M、L 等允许在美国长期学习、工作、交流或居住的非移民身份人群。

项目不是以阅读长篇攻略为核心的内容网站，而是一套交互式申请流程助手。用户选择目的地、签证类型和当前美国身份后，系统生成适用的申请路径，并通过步骤说明、材料 Checklist、条件分支和官方网站入口，引导用户逐步完成申请。

本站不会代替用户填写或提交官方申请表，不接收护照、银行流水等申请材料，也不提供法律意见。

## 2. 目标用户

### 2.1 服务对象

- 持中华人民共和国护照
- 当前居住或停留在美国
- 计划从美国申请第三国签证
- 当前持有或维持以下一类美国非移民身份：
  - F 类：学生及家属，包括 F-1、F-2、OPT 和 STEM OPT
  - H 类：临时工作者及家属，包括 H-1B、H-4 等
  - J 类：交流访问者及家属，包括 J-1、J-2
  - M 类：职业或非学术学生及家属，包括 M-1、M-2
  - L 类：跨国公司内部调动人员及家属，包括 L-1、L-2
- 原则上以年满 18 岁的成年人为主要流程用户

### 2.2 条件覆盖人群

以下人群不直接套用默认流程，需要根据目的国、签证类型、官方规则和用户具体情况决定是否适用：

- 持 B-1、B-2 或 B-1/B-2 签证在美国短期停留的用户
- 已经在中国递交或获批申请，但希望在美国完成护照递交或贴签的用户
- 未满 18 岁的未成年人

未成年人可能需要额外文件，例如父母或监护人同意书、出生证明、监护关系证明和父母身份证明。实际要求必须根据目的国和受理机构的官方规定确认。

### 2.3 非目标用户

- 当前主要居住在中国大陆的申请人
- 从中国大陆递交签证申请的用户
- 美国公民
- 美国永久居民
- 非中国护照持有人
- 需要个案法律意见或移民身份判断的用户

已经在中国完成申请、目前人在美国且仅希望完成护照递交或贴签的用户，不因申请始于中国而自动排除，但必须进入单独的条件判断流程。

如果用户不属于本站覆盖范围，系统应明确说明当前流程不适用，并提供相应政府、使领馆或官方签证中心网站，而不是继续给出可能错误的申请指导。

## 3. 产品目标

用户完成一条申请流程后，应当能够：

1. 判断当前流程是否大致适用于自己。
2. 了解整个申请由哪些阶段组成。
3. 知道每个阶段需要完成什么任务。
4. 根据自己的美国身份获得对应材料清单。
5. 理解每项材料的用途、来源和注意事项。
6. 在适当的步骤进入官方网站完成正式操作。
7. 返回本站记录完成状态并继续下一步。
8. 了解递交申请后的生物信息采集、补件、护照递交等后续流程。

## 4. 产品原则

### 4.1 任务优先

页面应优先告诉用户“下一步做什么”，补充解释按需展开。避免把用户首先带入篇幅较长的攻略文章。

### 4.2 官方来源优先

费用、材料要求、申请入口、处理流程等关键内容必须引用政府部门、使领馆或官方签证中心来源。

### 4.3 区分规则与经验

所有内容应尽可能标明性质：

- 官方要求
- 本站整理
- 通常建议
- 条件适用
- 真实申请经验（DP）

不得把个别申请人的经验描述成普遍适用的官方规则。

### 4.4 不收集敏感信息

本站不要求用户输入或上传以下信息：

- 护照号码或护照扫描件
- 出生日期
- 银行账户或资金证明
- 美国签证号码
- SEVIS ID
- A-Number
- 申请表内容
- 支付信息

系统只保存流程选择和任务完成状态。

### 4.5 用户保有控制权

用户可以返回上一步、修改回答、跳过非强制任务、查看未完成事项和重置本地进度。

## 5. 核心用户流程

```text
确认中国护照及当前美国身份
→ 系统加载对应身份配置
→ 选择目的地国家和签证类型
→ 完成适用性筛选
→ 查看个性化流程总览
→ 完成申请前准备
→ 完成材料 Checklist
→ 前往官方网站填写并递交申请
→ 返回本站确认完成状态
→ 完成递交后的后续步骤
→ 收到护照和签证并核对结果
→ 可选提交匿名时间线
```

身份确认是流程入口，不是材料阶段中的附加问题。系统根据身份加载对应的流程配置、材料清单、条件分支和文案。

0.1 版本只实现 F-1 学生配置，但数据结构和页面组件不得把 F-1 规则写死，以便后续增加 OPT、H、J、M、L 等配置。

## 6. 流程阶段定义

### 6.1 阶段一：适用性筛选

系统通过少量问题判断当前流程是否适用。

可能包括：

- 是否持中国护照
- 是否目前人在美国
- 当前美国身份
- 当前身份或签证类别是否属于 F、H、J、M、L 或 B
- 当前在美停留属于长期居住、学习、工作、交流还是短期访问
- 是否年满 18 岁
- 申请目的
- 申请是否已经在中国递交或获批
- 是否只需要在美国完成护照递交或贴签
- 是否已有有效目的国签证
- 是否属于特殊或紧急申请情况

系统只能给出流程适用性提示，不应声称用户一定符合签证资格或一定会获批。

### 6.2 阶段二：流程总览

向用户展示：

- 可能需要申请的签证类型
- 主要申请阶段
- 当前支持的美国身份
- 官方费用
- 官方处理时间查询入口
- 是否可能需要采集生物信息
- 是否可能需要递交护照
- 最近核验日期
- 免责声明

用户确认后开始申请准备。

### 6.3 阶段三：申请前准备

用于确认用户具备开始申请所需的基础条件，例如：

- 护照仍在有效期内
- 已确认自己的美国身份文件
- 已确定大致旅行目的和日期
- 已了解申请费用
- 已了解整个流程可能需要的时间

### 6.4 阶段四：材料 Checklist

材料清单根据国家、签证类型、美国身份、年龄、申请起始地点和用户回答动态生成。

材料分为：

- 通用材料
- 身份专属材料
- 未成年人附加材料
- 护照递交或贴签专属材料
- 条件适用材料
- 建议材料

每项材料应包含：

- 材料名称
- 是否必须
- 适用人群
- 简短说明
- 准备建议
- 常见错误
- 官方来源
- 完成状态

### 6.5 阶段五：官方申请

当用户需要填写表格、注册账户、上传材料、预约或缴费时，本站提供官方网站链接。

跳转前应明确提示：

> 你即将离开本站并进入官方申请系统。本站不会代替你填写或提交申请，也不会接收你的个人申请材料。

本站可以在跳转前提供准备提示，但不复制官方表格，不模拟官方提交，也不要求用户把填写结果录入本站。

用户完成官方操作后，返回本站勾选相应任务并继续流程。

### 6.6 阶段六：递交后流程

递交后的步骤可能包含条件分支：

```text
是否收到生物信息采集通知？
├── 是：进入预约和采集步骤
└── 否：继续等待或确认是否无需采集

是否收到补件通知？
├── 是：按照通知提交补充材料
└── 否：继续等待

是否收到护照递交通知？
├── 是：进入护照递交或贴签步骤
└── 否：继续查看申请状态
```

每个分支必须提醒用户以其收到的官方通知为准。

### 6.7 阶段七：申请完成

最终确认事项可能包括：

- 已收到官方决定
- 已取回护照
- 已核对姓名和护照号码
- 已核对签证类别和有效期
- 已保存申请记录和收据
- 已了解签证不等于保证入境

## 7. Checklist 交互规则

### 7.1 任务类型

每项任务应属于以下一种：

- `required`：核心必做事项
- `recommended`：建议完成，但不阻止继续
- `conditional`：满足特定条件时出现
- `informational`：只需阅读确认

### 7.2 任务状态

首期建议支持：

- 未完成
- 已完成
- 暂时跳过
- 不适用

### 7.3 下一步规则

- 必做事项未完成时，系统可以提醒用户，但不应永久锁死流程。
- 用户选择继续时，应展示尚未完成的必做事项。
- 建议事项可以跳过。
- 条件事项仅在适用时显示。
- 用户修改身份、年龄、申请阶段或其他筛选答案后，应重新计算适用任务。

### 7.4 进度计算

总体进度只计算当前适用的核心步骤和任务，不计算隐藏或不适用事项。

进度应被描述为“本站流程完成度”，不能让用户误以为它代表官方申请审理进度。

```text

├── /apply/[country]/[visaType]
│   ├── /eligibility
│   ├── /overview

│   └── /complete
├── /about
├── /privacy

```

最终路由可以根据技术原型调整，但用户应始终知道：

- 当前位于哪个阶段
- 已经完成哪些阶段
- 下一步是什么
- 如何返回流程总览

## 9. 内容结构

项目内容分为三层。

### 9.1 流程层

定义申请阶段、顺序、分支和完成条件。

### 9.2 任务层

定义用户在每一步需要完成的 Checklist 项目。

### 9.3 解释层

为任务提供材料说明、注意事项、常见问题、官方来源和真实经验。

MDX 可以继续用于解释层内容，但不再作为主要用户流程的组织方式。

## 10. 初步数据模型

以下结构仅用于表达产品需求，具体实现需在首条流程设计完成后确定。

```ts
type ApplicationFlow = {
  id: string;
  version: string;
  country: CountryCode;
  visaType: string;
  statusConfig: string;
  lastVerified: string;
  steps: ApplicationStep[];
};

type ApplicationStep = {
  id: string;
  title: string;
  description: string;
  items: ChecklistItem[];
  officialLinks?: OfficialLink[];
};

type ChecklistItem = {
  id: string;
  title: string;
  type: "required" | "recommended" | "conditional" | "informational";
  applicableTo?: UsStatus[];
  description?: string;
  sourceUrl?: string;
  conditions?: StepCondition[];
};

type OfficialLink = {
  label: string;
  url: string;
  organization: string;
  purpose: string;
};

type StepCondition = {
  field: string;
  operator: "equals" | "includes";
  value: string | boolean;
};
```

建议将身份差异放入独立配置：

```ts
type StatusConfig = {
  id: string;
  status: UsStatus;
  label: string;
  eligibilityNotes: string[];
  requiredDocuments: ChecklistItem[];
  recommendedDocuments: ChecklistItem[];
  stepOverrides?: Record<string, Partial<ApplicationStep>>;
};
```

0.1 版本只提供 `f1` 配置。流程引擎通过配置 ID 获取材料与步骤，不在 React 组件中使用大量 `if (status === "F1")` 判断。

## 11. 本地进度保存

MVP 不设置账号和数据库，使用浏览器本地存储保存：

- 当前流程
- 用户选择的美国身份
- 非敏感筛选答案
- 当前步骤
- 已完成的任务 ID
- 已跳过或标记不适用的任务 ID

示例：

```json
{
  "flowId": "ca-visitor",
  "status": "F1",
  "currentStep": "documents",
  "completedItems": ["passport-check", "passport-scan", "valid-i20"],
  "skippedItems": ["optional-itinerary"]
}
```

页面应明确说明：

- 进度只保存在当前设备和浏览器中。
- 清除浏览器数据后进度可能丢失。
- 本站不会保存用户的申请材料或官方申请表内容。

## 12. MVP 范围

### 12.1 首条完整流程

首个 MVP 聚焦：

> 持中国护照、年满 18 岁、目前以 F-1 身份在美国学习的用户，从零开始申请加拿大访客签证，直至收到贴有签证的护照。

0.1 实际支持：

- F-1 在读学生
- 年满 18 岁
- 从美国在线递交新的加拿大访客签证申请

产品结构预留但 0.1 不开放：

- OPT、STEM OPT、F-2
- H、J、M、L 类身份
- B-1/B-2 短期访客
- 已经在中国申请、希望在美国完成护照递交或贴签的用户
- 未满 18 岁的申请人

暂不覆盖：

- 美国永久居民

### 12.2 MVP 必须包含

1. 适用性筛选
2. 美国身份、年龄和当前申请阶段选择
3. 个性化流程总览
4. 动态材料 Checklist
5. Checklist 项目说明
6. 官方来源链接
7. 官方申请系统跳转
8. 递交后流程和条件分支
9. 本地进度保存
10. 流程完成度
11. 返回、跳过和重置能力
12. 375px 移动端适配
13. 免责声明和隐私说明
14. 收到签证后的可选匿名时间线问卷

### 12.3 MVP 暂不包含

- 用户注册和登录
- 云端进度同步
- 用户材料上传
- 官方表格自动填写
- 代预约、代缴费或代提交
- 护照或身份信息存储
- AI 拒签概率判断
- 个性化法律意见
- 日本和韩国的完整申请流程
- 用户公开评论或社区功能

## 13. 匿名时间线调研

### 13.1 目标

在用户完成流程后，可选邀请其提交关键日期。数据量达到最低门槛后，用于展示本站用户样本中的大致处理时间。

该统计不能替代 IRCC 官方处理时间，也不能承诺个案结果。

### 13.2 建议采集字段

- 申请提交日期
- 收到生物信息采集通知日期
- 完成生物信息采集日期
- 收到补件通知日期（如有）
- 提交补件日期（如有）
- 收到护照递交通知日期
- 寄出或递交护照日期
- VAC 开始处理日期（如用户知道）
- 护照寄回日期
- 收到护照日期
- 申请结果：批准、拒签、撤回或仍在处理中
- 美国所在州
- 是否首次采集加拿大生物信息

不采集姓名、邮箱、护照号码、UCI、申请号、学校名称、具体住址或上传文件。

### 13.3 展示方式

- 样本不足时仅显示“数据收集中”。
- 达到最低样本量后显示中位数，不优先显示容易受极端值影响的平均数。
- 可以同时显示第 25 至第 75 百分位区间、样本量和数据更新时间。
- 按“提交至收到护照”“生物信息采集后至护照递交通知”“护照递交至收回”等阶段分别统计。
- 官方处理时间与本站用户样本必须分区展示。
- 拒签、撤回和仍在处理中样本不得混入“收到签证耗时”。

### 13.4 数据实现边界

0.1 可以先完成问卷字段和交互设计，不必立即建立公开统计系统。正式收集跨用户数据需要服务端存储、隐私说明、滥用防护和数据清理机制，因此不属于纯 `localStorage` 范围。

## 14. 内容核验要求

每条流程在发布前必须核验：

- 签证类型是否正确
- 官方申请入口是否有效
- 当前费用及币种
- 材料要求
- 照片和文件格式要求
- 生物信息采集规则
- 护照递交流程
- 官方处理时间查询入口
- 美国不同领区或身份是否存在差异
- 最近核验日期

内容来源优先级：

1. 目的国政府部门
2. 驐美使领馆
3. 官方签证申请中心
4. 官方公告和表格说明
5. 第三方经验文章
6. 真实申请 DP

## 15. 成功标准

MVP 成功不以文章数量衡量，而以用户能否完成一条端到端流程衡量。

初步验收标准：

- 用户能在移动端独立走完加拿大访客签证指导流程。
- 用户能明确区分本站任务和官方申请操作。
- Checklist 会根据美国身份显示不同材料。
- 退出并重新打开页面后，可以恢复本地进度。
- 所有关键申请步骤均有官方来源。
- 网站不收集或保存敏感申请信息。
- 用户不会因本站措辞误以为获得了签证资格或批准保证。
- F-1 用户能够从身份确认开始，一直走到收到并核对加拿大签证。

## 16. 风险与待确认问题

### 16.1 内容风险

- 官方政策可能频繁变化。
- 不同使领馆或签证中心可能有地区差异。
- B-1/B-2 短期访客是否可以在美国递交或完成后续步骤，可能受受理资格和停留情况限制。
- 已经在中国申请的用户能否转为在美国递交护照或贴签，可能取决于个案通知和官方签证中心规则。
- 未成年人材料要求可能因目的国、领区、同行人和监护情况而不同。
- “建议材料”和“官方必需材料”容易被混淆。
- 个别用户情况可能无法被标准流程覆盖。

### 16.2 产品风险

- 过多强制 Checklist 可能使用户无法继续。
- 进度百分比可能被误解为官方申请进度。
- 用户从官方网站返回本站的路径可能中断。
- 条件分支过早抽象可能增加不必要的技术复杂度。
- 用户自行填写的时间线可能存在记忆误差、重复提交或异常值。

### 16.3 待确认事项

- 首条加拿大流程覆盖普通访客、探亲和商务中的哪些目的。
- B-1/B-2 用户满足哪些条件时可以进入流程。
- 已在中国申请的用户能否以及如何在美国完成护照递交或贴签。
- 成年人与未成年人是否采用独立流程，还是通过条件分支处理。
- 是否允许用户在没有完成必做任务时继续。
- F、H、J、M、L 各类别内部哪些子身份需要独立路径。
- 是否需要针对不同州或领区调整流程。
- 是否需要提供材料清单打印或导出功能。
- 真实 DP 在流程中的展示位置和收录标准。
- 匿名时间线统计的最小公开样本量。
- 0.1 是否只设计问卷，还是同时实现跨用户数据收集。

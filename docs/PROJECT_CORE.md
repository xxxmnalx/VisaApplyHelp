# VisaApplyHelp 项目核心指导

> 文档性质：长期产品与架构原则  
> 适用范围：产品设计、内容编写、前端实现、未来认证与数据库建设  
> 更新日期：2026-06-23

## 1. 一句话定义

VisaApplyHelp 是一套面向在美中国护照持有人的第三国签证申请步骤助手。

它不以“让用户读完一篇攻略”为目标，而是根据用户当前的美国身份加载适用流程，通过 Checklist、官方入口、条件步骤和进度记录，陪用户从开始准备走到收到签证。

## 2. 为什么要做

在美国生活的中国护照持有人申请加拿大、日本、韩国等第三国签证时，往往需要同时理解：

- 目的国签证规则；
- 自己当前的美国身份；
- 美国境内的申请、指纹和贴签安排；
- 官方系统之外容易遗漏的准备工作；
- 递交申请之后仍然存在的多个阶段。

传统攻略通常把这些信息写成一篇长文。用户读完后仍需要自己提取材料清单、判断适用条件、寻找官方入口并记录进度。

本项目把“信息”转化为“可执行流程”：

```text
确认身份
→ 加载适用配置
→ 完成逐步 Checklist
→ 在正确节点进入官方网站
→ 返回本站继续后续步骤
→ 收到并核对签证
```

## 3. 面向人群

### 3.1 长期目标用户

- 持中华人民共和国护照；
- 当前居住或合法停留在美国；
- 计划从美国申请第三国签证；
- 美国身份属于 F、H、J、M、L 等非移民类别；
- 希望获得一条清晰、可信、可保存进度的申请路径。

### 3.2 0.1 实际支持

- 年满 18 岁；
- 中国普通护照；
- 美国 F-1 在读学生；
- 从美国申请加拿大访客签证；
- 从零开始申请，直至收到贴有签证的护照。

### 3.3 当前不覆盖

- 美国公民；
- 美国永久居民；
- 从中国大陆完成整套申请的用户；
- 需要复杂法律或移民身份判断的个案；
- 用户材料托管、代填表、代提交或代付款。

未开放的人群不能被强行导入最相近的流程。系统必须明确提示“暂未支持”，避免用户误用。

## 4. 产品价值

### 4.1 对用户

- 不必从长文中自行拆解下一步；
- 根据身份获得更相关的材料与说明；
- 在正确节点进入政府或官方签证中心网站；
- 可以暂停并恢复流程；
- 清楚区分官方要求、本站整理和申请经验；
- 不需要把护照、申请号或财务资料交给本站。

### 4.2 对项目

- 一套流程配置可以被统一页面渲染；
- 新身份和新国家主要通过新增配置扩展；
- 官方规则更新时可以定位到具体来源和步骤；
- 未来可以在不重写 UI 的情况下接入登录和数据库；
- 匿名时间线数据积累后，可以提供更贴近真实用户的阶段耗时参考。

## 5. 产品底线

### 5.1 官方优先

关键要求、费用、申请入口、期限和递交方式必须有官方来源。第三方文章只用于理解常见操作和经验，不得覆盖官方规则。

### 5.2 不作批准承诺

本站只能帮助用户完成流程，不能判断一定符合资格、一定获批或一定在某个时间内收到结果。

### 5.3 最小数据原则

系统只保存完成流程所必需的非敏感状态：

- 流程 ID 和版本；
- 身份类别代码；
- 当前步骤；
- Checklist 状态；
- 用户自愿记录的日期级时间线；
- 创建与更新时间。

系统不保存：

- 护照号码或扫描件；
- UCI、IRCC 申请号或其他官方申请编号；
- 出生日期；
- I-20、SEVIS ID、A-Number；
- 具体学校、住址或银行资料；
- 官方账户密码；
- 申请表答案和证明文件。

### 5.4 用户拥有进度

用户可以查看、修改、跳过适用的非强制项、清除进度，并在未来登录系统中导出或删除自己的记录。

### 5.5 估算只是估算（0.2）

「拿签 ETA」按用户选择的提交日叠加各阶段经验 / 官方区间得出，是估算而非保证、也不是最长上限。官方处理时间只覆盖审批本身，不含生物信息采集与护照邮寄；阶段周数不得硬编码，官方处理段须指向官方查询工具并标注核验日期，UI 必须明示「估算、非保证」。

### 5.6 国籍参数化（0.2）

是否需要签证、需要哪种入境文件由国籍决定，不得把任何「某国籍 = 某文件」写死。配置以 `nationality` 表达，并把官方「是否需要签证或 eTA」判断工具作为权威出口。当前内容仍只做中国（visa-required，TRV）。

## 6. 核心领域模型

项目长期保持四个核心概念：

### FlowConfig

描述某个“国家 + 签证类型 + 美国身份 + 适用范围”的完整流程定义。

### FlowStep

描述流程中的一个阶段，包括标题、说明、任务、官方来源和可选时间节点。

### FlowProgress

描述某位用户在某个 FlowConfig 版本上的非敏感完成状态。

### ApplicationRun

未来数据库中的一次用户申请流程实例。它是 FlowProgress 的服务端持久化表达，不包含签证材料本身。

## 7. 架构原则

项目采用 Next.js 模块化单体，而不是提前拆分独立前后端服务。

```text
React 页面与组件
        ↓
领域逻辑与应用服务
        ↓
Repository 存储契约
        ↓
localStorage（0.1） / 服务端数据库（未来）
```

### 7.1 展示层

`app/` 和 `components/` 负责路由、可访问性、视觉展示和用户交互，不承载签证身份规则或数据库实现细节。

### 7.2 领域层

`lib/domain/` 存放纯函数，例如：

- 创建和规范化进度；
- 更新任务状态；
- 计算完成度；
- 判断必做项是否完成；
- 未来的版本迁移和流程分支判断。

领域函数不得直接访问浏览器、数据库或网络。

### 7.3 配置层

`config/flows/` 保存签证流程定义。页面通过注册表查找配置，不直接导入特定国家或身份的规则。

新增身份或国家时，优先新增配置，而不是复制页面或在组件中增加大量条件判断。

### 7.4 Repository 层

`lib/repositories/` 定义并实现进度存储接口。

0.1 使用 localStorage Repository。未来登录和数据库上线后，增加远程 Repository 或服务端 DAL，不改变领域模型和主要 UI 契约。

### 7.5 服务端层（未来）

未来使用 Next.js Server Actions、Route Handlers 和 Data Access Layer：

- Server Actions 处理登录用户的进度修改；
- Route Handlers 仅用于确实需要 HTTP 端点的场景；
- DAL 统一完成认证、授权、输入验证和数据库访问；
- Server Components 直接调用 DAL，不请求本站自己的 API。

## 8. 路由原则

流程页面统一使用：

```text
/apply/[country]/[visaType]/[status]/[step]
```

路由参数必须能从流程注册表解析为唯一 FlowConfig。不得为每个身份复制一套页面。

稳定标识使用英文 slug 和不可变 ID；中文标题可以随内容优化而改变。

## 9. 进度与同步策略

### 9.1 0.1

- 无账号；
- localStorage 保存；
- 单浏览器可恢复；
- 离线可用；
- 不上传服务器。

### 9.2 未来登录后

- 用户勾选后 UI 立即更新；
- 后台异步保存到数据库；
- 网络失败时保留本地队列；
- 恢复网络后重试；
- 使用 `revision` 处理多设备更新冲突；
- 登录时允许用户把本地匿名进度认领到账号。

“实时保存”指即时反馈和后台同步，不默认意味着使用 WebSocket。

## 10. 未来数据库边界

建议采用 PostgreSQL，最小业务表为：

```text
application_runs
application_task_states
application_timeline_events
```

匿名耗时调研应使用独立表和单独同意，不直接把私人进度自动公开为统计样本。

认证由成熟的认证库或托管服务提供，不自行实现密码系统。所有数据库操作必须在服务端验证当前用户对记录的所有权。

## 11. 内容生产原则

每个流程发布前必须确认：

- 适用人群和排除条件；
- 完整的端到端步骤；
- 每个任务属于必做、建议、条件适用或阅读确认；
- 关键结论对应的官方来源；
- 易变信息的最近核验日期；
- 不同身份带来的材料差异；
- 用户收到签证前的所有后续阶段；
- 免责声明和隐私边界。

## 12. 版本策略

- `FlowConfig.version` 用于标识流程规则版本；
- 不兼容的任务 ID 或步骤变化需要进度迁移策略；
- 已发布的 ID 尽量保持稳定；
- 删除任务前考虑旧进度如何处理；
- 内容更新必须写入 `UPDATE.md`；
- 重大产品决定同步更新本文档。

## 13. 成功标准

项目成功不以文章数量或页面数量衡量，而以以下结果衡量：

- 目标用户能否确认自己是否适用；
- 能否知道当前应该做什么；
- 能否从零走到收到签证；
- 能否轻松找到官方入口；
- 能否暂停并恢复；
- 是否始终保护用户隐私；
- 新身份和国家能否通过配置低成本扩展；
- 未来数据库上线时是否无需重写主要流程 UI。
